# Чунда — ИИ-бот для Twitch

Бот отвечает на вопросы из чата по команде `!бот`: зритель пишет `!бот Привет!`, а Чунда отвечает от отдельного Twitch-аккаунта. Основная модель — `deepseek-v4.1-flash` через API `ai.starimg.ru`, запасная — `deepseek-v4-pro`. Характер и стиль ответов заданы в `bot.py`.

## Что понадобится

- Компьютер с Python 3.10 или новее. Он должен быть включён, пока бот работает на стриме.
- Логин Twitch-канала и отдельный Twitch-аккаунт для бота.
- **Client ID** приложения типа **Public** из [Twitch Developer Console](https://dev.twitch.tv/console/apps). Client Secret не нужен.
- API-ключ `ai.starimg.ru` с доступом к моделям `deepseek-v4.1-flash` и `deepseek-v4-pro`.

## Установка и первый запуск

1. Скачайте проект через **Code → Download ZIP** на GitHub и распакуйте архив.
2. На Windows запустите `start.bat`. На macOS или Linux откройте терминал в папке проекта и выполните `python3 start.py`.
3. Введите логин канала, логин аккаунта бота, Twitch Client ID и API-ключ. Для Base URL нажмите Enter, чтобы использовать `https://ai.starimg.ru/v1`, или введите адрес из кабинета API.
4. Когда Twitch предложит авторизацию, войдите **под аккаунтом бота** и разрешите доступ к чату.
5. После подключения напишите в чат `!бот Привет, Чунда!`.

При следующих запусках достаточно снова открыть `start.bat` или выполнить `python3 start.py`. Чтобы изменить настройки, запустите `start.bat --setup` или `python3 start.py --setup`.

Настройки сохраняются в локальном `.env`, токен Twitch — в `.twitch_token.json`. Эти файлы исключены из Git. Не публикуйте их и не отправляйте другим людям.

## Память о стримере и зрителях

При первом запуске бот создаёт локальный `memory.json` из [memory.example.json](memory.example.json). Остановите бота сочетанием Ctrl+C, отредактируйте `memory.json` и запустите его снова. При последующих запусках файл не перезаписывается.

- `streamer.facts` — короткие факты о стримере.
- `streamer.jokes` — шутки и особенности канала.
- `viewers` — карточки зрителей, которых бот должен узнавать.

В шаблоне есть объект `_example_viewer_copy_into_viewers`. Это образец: бот его игнорирует. Скопируйте объект в массив `viewers` и замените значения:

```json
{
  "login": "pelmen",
  "user_id": "",
  "facts": ["Любит хорроры"],
  "jokes": ["Можно дружески подколоть про скримеры"],
  "avoid": ["Не шутить про личную жизнь"]
}
```

`login` — Twitch-логин маленькими латинскими буквами, без `@`. `user_id` можно оставить пустым: тогда карточка ищется по логину. Если указать числовой Twitch ID, бот узнает зрителя и после смены логина. В `facts` записывайте только то, что допустимо повторить в эфире; `jokes` задаёт темы для шуток, а `avoid` — темы, которых следует избегать.

Бот не сохраняет историю чата и не пополняет карточки автоматически. Для ответа AI-сервису передаются общие заметки о стримере и карточка только того зрителя, который задал вопрос. `memory.json` исключён из Git: не добавляйте заполненный файл в публичный репозиторий.

## Если бот не запускается

- Убедитесь, что установлен Python 3.10+ и он доступен из командной строки. На Windows после установки Python может понадобиться открыть `start.bat` заново.
- Проверьте логины, Twitch Client ID и Base URL командой запуска с `--setup`.
- Убедитесь, что при авторизации Twitch выбран именно аккаунт бота.
- Проверьте, что API-ключ действителен и у него есть доступ к основной и запасной моделям.
- Если ошибка указывает на `memory.json`, проверьте синтаксис JSON и структуру полей по шаблону.

Для помощи с ошибкой достаточно передать её текст. Не передавайте содержимое `.env`, `.twitch_token.json` или заполненного `memory.json`.

## Дополнительно

- Команда: `!бот вопрос`; максимум 400 символов вопроса и 300 символов ответа.
- Временных ограничений между вопросами нет. Бот обрабатывает ответы по одному; в очереди может ждать до 10 вопросов. Если она заполнена, новый вопрос отклоняется с записью причины в консоль.
- Если основная модель не отвечает, возвращает пустой ответ или ошибку 502/503/504, бот пробует `deepseek-v4-pro`. После трёх подряд таких сбоев он обращается сразу к запасной модели в течение 5 минут, затем проверяет основную снова. На каждый запрос к модели отводится до 20 секунд, поэтому переключение может увеличить ожидание ответа до 40 секунд.
- Каждый запрос к модели может расходовать баланс API.
- Проверка кода: `python -m unittest discover -s tests -v` (на macOS/Linux используйте `python3`).
