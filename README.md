# Twitch AI Bot

Приложение отвечает в Twitch-чате на вопросы из награды за баллы канала. Зритель получает награду и вводит вопрос, бот отправляет его в AI API и публикует ответ от отдельного Twitch-аккаунта.

Можно настроить канал, название награды, AI-провайдера, модели и системный промпт. **Промпт по умолчанию пуст:** характер, язык и правила общения задаёте вы. Интерфейс выполнен в нейтральных серых цветах. Один запущенный экземпляр обслуживает один выбранный канал. Дополнительно можно включить самостоятельные реплики по контексту обычного чата; по умолчанию этот режим выключен.

## Что понадобится

- Twitch-канал с доступом к наградам за баллы канала и отдельный аккаунт бота.
- Client ID приложения типа **Public** из [Twitch Developer Console](https://dev.twitch.tv/console/apps). Client Secret не требуется.
- API-ключ, HTTPS Base URL и ID модели у провайдера, совместимого с Chat Completions: `POST /chat/completions`, ответ в `choices[0].message.content`.
- Для готового приложения — Windows. Для исходников — Python 3.10+; сборка Windows проверяется на Python 3.12.

Компьютер и приложение должны работать, пока бот отвечает зрителям.

Для вкладки **Тестирование** нужны только AI Base URL, API-ключ и ID хотя бы одной модели. Twitch-канал, аккаунт бота и Client ID не требуются.

## Быстрый запуск на Windows

### Готовое приложение

1. Откройте [сборки Windows для ветки dev](https://github.com/dudll300/twitch-ai-bot/actions/workflows/windows-gui.yml).
2. Выберите успешный запуск после обновления приложения, скачайте артефакт **TwitchAIBot-Windows** и распакуйте его. Для скачивания артефактов может потребоваться вход в GitHub.
3. Запустите `TwitchAIBot.exe`. Python устанавливать не нужно.

### Из исходников

Скачайте или клонируйте ветку `dev` и запустите `launch_gui.bat`:

```powershell
git clone --branch dev https://github.com/dudll300/twitch-ai-bot.git
cd twitch-ai-bot
.\launch_gui.bat
```

Скрипт создаёт `.venv` и устанавливает зависимости при необходимости. Для первого запуска нужен интернет.

## Настройка бота

1. В панели управления Twitch создайте награду за баллы канала. Название и стоимость выберите сами. Включите **обязательный ввод текста**.
2. В разделе **Подключение** укажите канал, логин аккаунта бота, Twitch Client ID и название награды. Пример названия по умолчанию — `Вопрос ИИ`. Название должно совпадать с Twitch; регистр букв не учитывается.
3. Заполните Base URL, API-ключ и ID основной модели. Стрелка справа раскрывает список; ID можно также ввести вручную. Кнопка **Загрузить модели провайдера** получает полный каталог через API для введённого или сохранённого ключа. Автоматической загрузки нет. Недоступные модели отмечены, загрузка не меняет выбранный ID. При ошибке остаётся ручной ввод. Адрес `https://ai.starimg.ru/v1` и модели DeepSeek в начальном списке — примеры настроек.
4. При первом запуске в запасные модели подставляются `deepseek-v4-pro,deepseek-v4-flash` в этом порядке. Можно заменить их или очистить поле: пустой список означает, что вызывается только основная модель. Они используют тот же API-ключ и Base URL; доступность определяется провайдером. Существующие настройки, включая пустой список, не изменяются.
5. В разделе **Поведение** заполните общий системный промпт, подготовьте пресет или сгенерируйте его по своим пожеланиям. Можно оставить поле пустым. Дополнительного встроенного персонажа или особого тона для владельца канала нет.
6. Нажмите **Запустить бота**. Настройки сохранятся. При первом запуске подтвердите вход в Twitch сначала под аккаунтом бота, затем под аккаунтом владельца канала. Нужный аккаунт, ссылка и код показаны в разделе **Активность**.
7. Дождитесь сообщения об ожидании вопросов и получите настроенную награду с текстом вопроса.

**Остановить** завершает процесс бота. Чтобы применить изменения подключения, промпта или профилей, остановите бота и запустите снова. Параметры самостоятельных реплик применяются во время работы. Кнопка **Очистить** в разделе **Поведение** удаляет текст из формы; сохраните его или запустите бота, чтобы применить очистку. При изменении канала, аккаунта бота или Client ID соответствующая авторизация запрашивается заново.

## Интерфейс

- **Подключение** — две колонки для Twitch и AI-сервиса.
- **Поведение** — общий системный промпт, бесплатные пресеты и AI-генератор с проверкой нового варианта.
- **Зрители** — поиск, добавление и редактирование личных инструкций.
- **Самостоятельные реплики** — включение, отдельные инструкции участия, предпросмотр, частота, контекст и журнал решений AI.
- **Активность** — авторизация, журнал и счётчики вопросов и ответов текущего запуска.

Кнопка меню слева от заголовка плавно скрывает и возвращает боковую панель. Статус бота остаётся видимым в шапке. Минимальный размер окна — 1240 × 820, со скрытым меню — 1000 × 820 логических пикселей; на небольшом экране он ограничивается доступной рабочей областью, а длинные разделы прокручиваются.

**Сохранить** или `Ctrl+S` сохраняет настройки подключения, промпт и профили, даже если вы ещё не ввели все данные подключения. Перед запуском бот проверит обязательные поля. Несохранённые изменения этих разделов отмечены внизу окна; при закрытии приложение предложит их сохранить. Пока бот работает, эти разделы доступны для просмотра. На вкладке самостоятельных реплик действует отдельная кнопка **Применить** для её инструкций и числовых параметров.

## Пресеты и генератор промпта

Во вкладке **Поведение** есть отдельные секции **Создать новый промпт** и **Улучшить текущий промпт**, каждая со своими пожеланиями и кнопкой. Создание предлагает основы **По существу**, **Собеседник**, **С юмором**, **Дерзкий**, **Тёплая поддержка** и **Азартный напарник**. Пресеты описывают конкретные реакции и приёмы общения, включая примеры, которые нельзя механически повторять.

Выберите **Темперамент**: **Сдержанный**, **Живой**, **Энергичный** или **Взрывной**. Он определяет эмоциональность и подачу; частота юмора и использование мата задаются независимо. Характер не должен заменять ответ на вопрос. Укажите **Темы канала**, затем нажмите **Показать пресет · без AI API**. Пресеты создаются локально, работают без ключа и не расходуют баланс.

Для своего варианта опишите пожелания, например: «Часто шути, подкалывай зрителей и используй мат изредка, но отвечай по делу». Выберите точный ID **модели для генерации**, затем нажмите **Сгенерировать промпт**. По умолчанию предложена `gpt-6.1-sol`, но её доступность определяется вашим провайдером и ключом. Можно использовать `gpt-6-luna` или другую доступную модель. Кнопка **Загрузить модели провайдера** получает полный каталог только по запросу. При ошибке остаётся ручной ввод ID; запасные модели не подставляются. Модель генерации не меняет основную модель ответов бота.

Для доработки напишите в **Что доработать**, например: «Сохрани характер, но убери повторяющиеся фразы», и нажмите **Улучшить текущий промпт**. Можно оставить пожелания пустыми для уточнения формулировок. Передаётся текущий общий промпт из формы, включая несохранённые изменения; настройки и пожелания секции создания нового промпта в этот запрос не попадают. Темы ранее созданного приложением промпта сохраняются. Если общий промпт пуст, сначала создайте новый. Чекбокс переключения режимов больше не нужен.

Требуются только AI Base URL, введённый или сохранённый API-ключ и ID модели. Без ключа показана подсказка перейти в **Подключение**. **Генерация расходует баланс AI API.** Явные пожелания могут переопределять стиль, частоту юмора и лексику основы, но не обязательные правила защиты. Текст и параметры фиксируются на момент нажатия. HTTP выполняется вне GUI-потока с таймаутом 20 секунд. Во время запроса обе кнопки генерации заблокированы; закрытие окна отбрасывает результат. При смене ключа или Base URL во время запроса результат также отбрасывается. Некорректный или обрезанный ответ не заменяет предыдущий вариант.

Поле нового варианта увеличено по вертикали. На всех вкладках колесо над текстовым полем прокручивает его содержимое, если текст не помещается по высоте. Если весь текст помещается, прокручивается вкладка. На границах длинного текста прокрутка остаётся внутри поля; раскрытые списки моделей и списки зрителей тоже не переключают страницу на границах списка. Правило действует и для журналов и результатов тестирования.

В каждый пресет и сгенерированный вариант приложение само добавляет обязательный блок **Правила задачи и защиты**: ответ по существу, темы канала, отказ от посторонних заданий вроде написания калькулятора, непрофильных политических провокаций, подмены роли и раскрытия служебных инструкций. Правило политических споров одинаково для всех стран; нейтральное упоминание места, например привет зрителю из Тайваня, не должно вызывать отказ. Темы можно уточнить, но они не отменяют запрет посторонних заданий.

Обычные ответы допускают до **400 символов**. У ранее созданного приложением промпта обновляется только точно распознанный служебный блок с прежним лимитом 300; характер, темы и остальной текст сохраняются. В форме обновлённый вариант отмечается как несохранённый и записывается по кнопке **Сохранить**. Бот и тестирование также используют обновлённый блок при формировании обычного запроса, без записи в файл. Произвольные ручные ограничения и изменённые служебные блоки автоматически не переписываются.

Новый вариант остаётся отдельным редактируемым черновиком. Локальная проверка подтверждает длину, отсутствие управляющих символов и наличие неизменённого обязательного блока, **а не качество ответов или невозможность обхода**. Кнопка **Проверить этот вариант** открывает **Тестирование** с копией черновика, не заменяя общий промпт и не сохраняя файлы. Выберите модель ответов и обычный вопрос или готовый пример проверки. После сравнения можно нажать **Применить к общему промпту**; **Отменить замену** возвращает предыдущий текст. Изменения попадают в `prompt.txt` только после **Сохранить** или запуска бота. Для работающего бота потребуется остановка и повторный запуск. Настройки генератора и неприменённый вариант сохраняются только до закрытия окна.

**Промпт уменьшает риск нежелательного поведения, но не гарантирует защиту от всех атак и ограничений провайдера.** Проверяйте содержательные ответы, отказы и ложные отказы на выбранной модели. Запросы генератора и тестовые ответы не попадают в память, историю разговоров или журнал работающего бота; генератору не передаются профили, история и карточки памяти.

## Тестирование промпта и сравнение моделей

1. В **Подключении** заполните Base URL и API-ключ. Пустое поле ключа использует уже сохранённый ключ; введённый ключ имеет приоритет и не требует сохранения. Поля Twitch можно оставить пустыми.
2. Откройте **Тестирование** или нажмите **Проверить ответ** в **Поведении** либо у выбранного профиля в **Зрителях**. Переход не сохраняет настройки и сохраняет все черновики в интерфейсе.
   Для нового варианта генератора используйте **Проверить этот вариант**: над вопросом указано, что используется временный промпт. Кнопка **Вернуться к текущему общему промпту** отменяет только этот выбор, сохраняя вопрос и модели. В списке **Примеры для проверки поведения и защиты** есть обычный вопрос, юмор, просьба написать программу, политическая провокация, подмена инструкций, раскрытие промпта и нейтральное упоминание страны. Для каждого показано ожидаемое поведение; реальный ответ оцениваете вы. Пример не запускает запрос автоматически.
3. Введите вопрос и выберите отправителя: обычный зритель с необязательным пробным логином, конкретный профиль или **Владелец канала**. Последний режим имитирует роль без Twitch-логина и авторизации. Без пробного логина обычный зритель называется `test_viewer`.
4. Нажмите **Обновить список**, найдите модели поиском и отметьте несколько флажками. Для `https://ai.starimg.ru/v1` каталог запрашивается через `GET https://ai.starimg.ru/v1/models` с заголовком `Authorization: Bearer <API key>` — это каталог API для текущего ключа, без разбора HTML сайта и без списка из настроек. Для другого Base URL используется его `/models`. Недоступные модели, явно отмеченные каталогом, нельзя выбрать. Если API не сообщает доступность, она проверяется при запросе. При сбое каталога видна причина; ID можно добавить вручную.
5. Нажмите **Получить ответы**. Для каждой модели отдельно показываются её точный ID, ответ, длительность ожидания либо ошибка. Автоматической подмены запасной моделью нет; ошибка одной модели не скрывает остальные ответы.

Каталог занимает всю ширину вкладки и показывает больше строк. **Сбросить выбор** снимает все флажки, включая модели, скрытые поиском, сохраняя сам каталог и пробный вопрос. Колесо мыши прокручивает страницу или список, но не меняет числовые параметры и закрытые выпадающие списки.

На момент нажатия создаётся один неизменяемый снимок: текущий текст общего промпта, текущие инструкции, имена и переключатели всех профилей из интерфейса, вопрос, параметры AI и заметки из `memory.json`. Изменения в интерфейсе после нажатия действуют только на следующий тест. Сохранять промпт или профиль перед тестом не нужно. Для выбранного отправителя используется та же логика, что у бота: Twitch ID важнее логина, профиль с ID сопоставляется по ID, отключённая личная инструкция не применяется. Подходящая карточка памяти и заметки о канале добавляются независимо от переключателя инструкции.

Чтобы проверить узнавание другого человека, создайте профиль `lopotik`, задайте его инструкцию, затем выберите **Обычный зритель** и напишите, например, **«Расскажи про лоптика»**. Сохранять профиль перед тестом не требуется. В блоке контекста появятся найденный профиль, исходное упоминание, способ распознавания, применённая инструкция и заметки. Можно проверить русский ник, альтернативное имя, отключённый профиль и неоднозначное совпадение. Для проверки поведения на реальных авторах чата в самостоятельных репликах нужен подключённый чат.

Рядом с ответами показаны краткие выдержки применённого общего промпта, личной инструкции, заметок и профилей распознанных зрителей. При неоднозначном имени явно указано, что профиль не применён. **История реальных разговоров недоступна и в тесте не учитывается.** Формирование сообщений и распознавание общие с ботом: вопрос ограничен 400 символами, ответ — 400 символами одной строкой, запрос использует `max_tokens: 512`. Это верхний предел ответа, короткие реплики не дополняются до него.

**Тесты могут расходовать баланс AI API для каждой выбранной модели.** HTTP-запросы выполняются вне GUI-потока, до четырёх одновременно, с сетевым таймаутом 20 секунд; повторный запуск блокируется до завершения сравнения. Закрытие окна не ждёт сеть: уже начатый запрос может завершиться у провайдера, но его ответ будет отброшен, а оставшиеся запросы не запускаются.

Тест не запускает бота, не запрашивает OAuth, не публикует сообщения в Twitch и не меняет память, историю или журнал бота. Без существующего `memory.json` читается шаблон, локальная память не создаётся. API-ключ скрыт в поле ввода и удаляется из ответов и ошибок, если провайдер его повторил.

## Самостоятельные реплики

1. Откройте **Самостоятельные реплики**. По умолчанию режим выключен, выбран **Предпросмотр**.
2. Выберите **Характер участия**: **Осторожный** вступает при явном поводе, **Собеседник** поддерживает разговор, **Активный** допускает больше инициативы по свежей теме. Общий промпт задаёт характер, юмор и лексику. В отдельном поле **Инструкции самостоятельного участия** уточните, как бот должен поддерживать выбранный разговор. Например: «Поздравляй с победами коротко и без обязательной шутки; не связывай соседние сообщения разных тем». Настройте частоту и контекст, нажмите **Применить**. Тумблер, **Предпросмотр / Публикация** и характер участия сохраняются сразу; инструкции и числовые поля — вместе по кнопке.
3. Включите режим и запустите бота. При работающем боте изменения применяются без перезапуска, обычно в течение четверти секунды.
4. В предпросмотре решения модели, адресат, номера сообщений-оснований и предложенный текст появляются в журнале на этой вкладке. Чтобы отправлять реплики от аккаунта бота, выберите **Публикация**. Старые заготовки при переключении отменяются. Для самостоятельных реплик нужен подключённый чат; отдельного прогона сцен в «Тестировании» нет.

Редактор инструкций доступен всегда; ограничение — 10 000 символов. Пустое поле убирает дополнительные пожелания, обязательные правила участия и формат ответа задаются приложением. Кнопка **Вернуть стандартные инструкции** меняет только черновик текста; для сохранения нажмите **Применить**. Переключение режима или характера участия применяет сохранённые инструкции и не сохраняет незавершённый черновик. Сворачивание настроек, переход на другую вкладку и ошибка сохранения не теряют текущий текст.

Всегда видны числовые поля **Пауза между репликами** и **Максимум за час**. Остальные числовые параметры находятся в раскрываемом блоке **Расширенные настройки**, который по умолчанию свёрнут. Сворачивание не сбрасывает введённые значения; кнопка **Применить** сохраняет все параметры, включая скрытые.

Кнопка **Сбросить настройки** сразу сохраняет значения по умолчанию, выключает режим и возвращает **Предпросмотр**. Черновики инструкций и числовых параметров также сбрасываются. Журнал и счётчик уже выполненных отправок не очищаются.

| Параметр | По умолчанию |
| --- | --- |
| Пауза между репликами | 300 с |
| Максимум за час | 8 |
| Сообщений в контексте | 20 |
| Срок свежести контекста | 240 с |
| Случайная пауза между AI-проверками | 12–20 с |
| Последнее сообщение не старше | 60 с |
| Минимум сообщений | 3 |
| Минимум разных авторов | 2 |
| Максимальная длина реплики | 220 символов |
| Ожидание паузы в разговоре | 3 с |
| Максимальное ожидание фрагмента в непрерывном чате | 12 с |
| Срок актуальности ответа | 30 с |
| Максимум AI-запросов за час | 40 |

Прежние пределы диапазонов сняты для всех числовых параметров. Используются целые числа: время и лимиты за час могут быть нулевыми, размер контекста, число сообщений/авторов и длина реплики — положительными. Нулевой лимит реплик или AI-запросов отключает самостоятельные запросы. Сохраняется проверка согласованности: начало интервала не больше конца, ожидание паузы не больше максимального ожидания фрагмента, окно активности не больше срока свежести, минимум сообщений и авторов не больше размера контекста. Длина проверяется вместе с добавляемым `@логином`; для отправки в чат действует предел 450 символов даже при большем значении поля.

Бот хранит авторов, тексты, время, локальные ID и доступные Twitch ID сообщений, связи ответов и упоминания только в оперативной памяти. Связь ответа помогает отличать параллельные обсуждения; соседство строк само по себе не означает один разговор. Исключаются сообщения самого бота, команды с `!`, `/` или `.`, сообщения наград с соответствующей меткой Twitch, повторы и очевидный спам. Буфер чата очищается при выключении режима, изменении его настроек, переподключении и перезапуске. Пока режим выключен, обычный чат и новые ответы бота для инициативы не собираются, самостоятельные запросы не выполняются.

Новые сообщения запускают сбор короткого фрагмента обсуждения. Бот ждёт небольшую паузу, а в непрерывном чате — не дольше максимального ожидания; при этом соблюдает паузу между AI-проверками, лимиты и приоритет наград. В тихом чате таймер сам по себе не вызывает AI. Один уже проверенный фрагмент повторно не отправляется; одновременно выполняется максимум одна фоновая проверка из двух последовательных этапов, очереди заготовленных реплик нет.

Первый запрос выбирает **один связный разговор и конкретный повод**, либо возвращает решение промолчать. План содержит сообщения выбранной цепочки, адресата и тип полезного участия: ответ, реакцию, шутку или уточнение. При неясной связи сообщений безопаснее промолчать. Хотя бы одно основание должно быть новым сообщением; неизвестные ID и адресаты, не участвующие в выбранной цепочке, отклоняются.

Второй запрос выполняется только для допустимого непустого плана: модель получает **только выбранную цепочку**, её план, подходящие профили и заметки. Посторонние обсуждения из общей пачки в написание реплики не попадают. Генератор не может переключить адресата или основания. Если личные ограничения или недостаток фактов делают план неуместным, он может промолчать. Общий промпт задаёт характер, отдельные инструкции — способ участия; шутка необязательна. Приложение добавляет `@логин` адресата само. На посторонние задания инициативный бот должен молчать. Без изображения и звука стрима он не должен придумывать увиденные события.

Для написания реплики используются заметки о канале, подходящие карточки памяти и личные инструкции авторов и упомянутых зрителей выбранной цепочки. Также учитываются недавние действительно опубликованные ответы бота; для ответов по наградам сохраняется и вопрос, чтобы не отвечать на него заново. Собственные ответы не запускают новые проверки. Предпросмотр не выдаётся за опубликованный ответ. Эти сведения остаются в оперативной памяти. Автор определяется по Twitch ID с приоритетом над логином, упоминания — тем же распознаванием, что в наградах и тестировании. Отключённая личная инструкция не применяется; инструкция каждого профиля относится только к нему.

Настройки фиксируются на начало проверки. Перед вторым запросом и публикацией повторно проверяются настройки, награды, актуальность и наличие сообщений-оснований. Срок актуальности **общий для обоих этапов**: второй запрос получает оставшееся время, а просроченная реплика не публикуется. Ответ отбрасывается, если повод выпал из буфера, истёк срок ответа, чат ушёл далеко вперёд или несколько новых содержательных сообщений перестали пересекаться с темой основания. Одна новая строка не отменяет ответ автоматически. Это консервативные локальные проверки; отдельной модели-критика нет. Точные повторы без учёта регистра и пунктуации и близкие по словам реплики также пропускаются. Уже использованный повод не открывается заново только ради другой формулировки.

**Максимум за любые последние 60 минут задаётся в настройках; по умолчанию — 8 реплик.** Предпросмотр и публикация используют общий счётчик и паузу; `silent` лимит не расходует. Счётчик сохраняется между запусками. Попытка отправки с сетевой ошибкой тоже может занять место в лимите, чтобы переподключение не вызвало лишние публикации.

**Лимит AI-запросов отдельный: по умолчанию 40 за любые последние 60 минут.** Считается каждая попытка вызова API: молчание обычно расходует один, подготовленный ответ — два. Место резервируется перед запросом; ошибки и отменённые результаты также учитываются, счётчик сохраняется между запусками. Если на второй запрос не осталось бюджета или счётчик нельзя записать, реплика не генерируется. Старые файлы настроек и счётчика продолжают загружаться; существующие значения сохраняются, новые поля получают значения по умолчанию. Новый интервал 12–20 секунд применяется к новым настройкам; сохранённые ранее 45–90 секунд автоматически не заменяются.

Вопросы по награде имеют приоритет: их поступление отменяет подготовленную самостоятельную реплику. Фоновый AI работает в отдельном потоке и не занимает очередь платных ответов. Если канал отправки занят, самостоятельная реплика пропускается. Уже начатый HTTP-запрос может завершиться после выключения режима или поступления награды, но его результат будет отброшен.

Используется основная модель и тот же API-ключ, без перебора запасных моделей. Проверки расходуют баланс API, в том числе при решении промолчать. При ошибке AI или некорректном JSON реплика пропускается, следующая проверка откладывается минимум на две минуты. Журнал показывает решения, ошибки и опубликованные реплики; исходные сообщения чата туда не записываются. Разделение разговоров проверяется автоматическими сценами с подставными ответами API, но качество юмора и уместность на вашей модели нужно оценивать в **Предпросмотре**.

## Персональные ответы зрителям

1. Откройте **Зрители → + Добавить**.
2. Укажите Twitch-логин, `@логин` или ссылку вида `https://www.twitch.tv/username`. Используйте логин аккаунта, а не отображаемое имя чата.
3. Если знаете числовой **Twitch ID**, впишите его в соседнее поле. Можно использовать только ID, без логина. Если ID указан, профиль сопоставляется строго по нему: смена ника не влияет, а новый владелец старого ника не получает чужую инструкцию.
4. Впишите личную инструкцию, например: «Обращайся по имени Алекс. Отвечай дружелюбно и кратко. Не шути про возраст».
5. При необходимости заполните **Другие имена / ники** через запятую, например `лопотик, Лёха`. Кнопка **Добавить русский вариант** предлагает транслитерацию логина; исправьте её, если привычное написание другое. Для профиля только с ID альтернативные имена позволяют узнавать упоминания в тексте.
6. Нажмите **Сохранить** и запустите или перезапустите бота. Кнопка **Проверить ответ** позволяет проверить текущий черновик без сохранения и подключения Twitch.

К общему системному промпту добавляется инструкция текущего отправителя. Затем передаются заметки из памяти, отдельный контекст распознанных зрителей и история разговора отправителя. Личные инструкции могут уточнять обращение, язык и стиль, в том числе для владельца канала. При пустом общем промпте личная инструкция тоже работает. Идентичность отправителя берётся из события Twitch; текст «я другой пользователь» в вопросе не переключает его профиль. Инструкция упомянутого зрителя передаётся с явной привязкой: применять её при общении с этим человеком или обсуждении его, а не к остальным участникам.

Распознавание ищет целые ники и альтернативные имена без учёта регистра и `@`, учитывает `ё/е`, русский вариант латинского ника и обычные русские окончания. Например, `lopotik`, `лопотик`, `лопотика` и `лоптика` относятся к одному профилю. Для имён от 5 символов допускается одна небольшая опечатка, включая перестановку соседних букв; от 9 символов — до двух. Короткие имена распознаются только точно. Числа в никах не заменяются по сходству. Если одинаковое имя или равная по близости опечатка подходит нескольким профилям, инструкция по этому упоминанию не добавляется. Привычные прозвища и необычные формы лучше указать явно. Все профили при каждом запросе не отправляются: выбираются только относящиеся к текущему вопросу или контексту чата. Дополнительный AI-запрос для распознавания не нужен.

Логины сопоставляются без учёта регистра. Привязка только по логину требует ручного изменения профиля после смены ника. ID имеет приоритет, если одновременно подходит отдельный профиль по логину. Дублирующиеся логины и ID запрещены. Без подходящего профиля используется обычный общий промпт.

Переключатель **Включён** позволяет временно отключить личную инструкцию, в том числе при упоминании другими людьми. Заметки памяти применяются независимо. Удаление можно отменить до сохранения. Поиск работает по логину, ID и альтернативным именам. Лимиты: до 1000 профилей, до 10 000 символов на личную инструкцию, до 20 альтернативных имён по 64 символа. Альтернативное имя состоит из букв, цифр, подчёркиваний или дефисов, без пробелов; несколько имён разделяются запятыми. Совпадение имён между разными профилями допускается, но такое упоминание считается неоднозначным.

Профили сохраняются локально в `profiles.json` и используются также при консольном запуске. Формат остаётся `version: 1`; новое необязательное поле профиля `aliases` — список имён, например `["лопотик", "Лёха"]`. Старые файлы без него продолжают работать. По умолчанию список пуст. Этот файл отделён от `memory.json`: **профили задают инструкции**, а **память хранит факты и заметки**. При переносе приложения сохраните оба файла. Профили одной папки данных действуют для выбранного в ней канала; при смене канала проверьте, какие инструкции хотите оставить.

## Где хранятся настройки

| Файл | Содержимое |
| --- | --- |
| `.env` | Канал, награда, параметры AI и API-ключ |
| `prompt.txt` | Ваш системный промпт, до 20 000 символов; может быть пустым |
| `.twitch_token.json` | Токены аккаунта бота |
| `.twitch_broadcaster_token.json` | Токены владельца канала |
| `memory.json` | Заметки о канале и зрителях |
| `profiles.json` | Личные инструкции, логины и ID зрителей |
| `autonomous.json` | Режим, отдельные инструкции и параметры самостоятельных реплик |
| `autonomous-quota.json` | Время самостоятельных реплик и AI-проверок, текст последней реплики для лимитов и защиты от повторов |
| `bot-session.log` | Журнал последнего запуска из GUI |

В готовой сборке файлы находятся в `%APPDATA%\TwitchAIBot`, при запуске исходников — рядом с `app.py`. Открыть папку можно кнопкой **Папка с данными** в боковой панели. Все перечисленные файлы исключены из Git. Не публикуйте API-ключи, токены и личные заметки.

Для ручной настройки используйте [.env.example](.env.example). Сохранённые значения `.env` имеют приоритет над переменными окружения. GUI сохраняет строки в кавычках, чтобы названия наград и ключи с кавычками читались без искажений. Пустое поле API-ключа в GUI сохраняет прежний ключ.

### Переход со старой сборки

Новая сборка использует папку `%APPDATA%\TwitchAIBot`. Настройки прежней версии из `%APPDATA%\ChundaBot` можно перенести вручную: `.env`, `prompt.txt`, `memory.json` и файлы токенов. Собственные файлы автоматически не удаляются и не переписываются. Чтобы убрать прежний характер из сохранённого `prompt.txt`, откройте **Поведение**, нажмите **Очистить** и сохраните настройки. Укажите название уже существующей награды; без этого новая версия использует `Вопрос ИИ`. Запасные модели теперь задаются явно.

## Консольный запуск

На Windows откройте `start.bat`: он подготовит окружение и запустит мастер настройки. Для повторной настройки используйте `start.bat --setup`.

На Linux или macOS:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-bot.txt
python start.py
# Повторная настройка:
python start.py --setup
```

Мастер спрашивает канал, аккаунт бота, Client ID, награду, Base URL, ключ и модели. Enter сохраняет прежнее значение или предложенный вариант; `-` очищает список запасных моделей. Свой промпт запишите в `prompt.txt` и перезапустите бота. Без GUI библиотека PySide6 не нужна. GUI и консоль в одной папке используют общие настройки.

## Память о канале и зрителях

При первом запуске создаётся `memory.json` из [memory.example.json](memory.example.json). Остановите бота перед редактированием файла. Повторный запуск сохраняет существующие заметки.

- `streamer.facts` — факты о стримере и канале.
- `streamer.jokes` — шутки и особенности канала.
- `viewers` — карточки зрителей.

Объект `_example_viewer_copy_into_viewers` — образец, бот его игнорирует. Скопируйте карточку в массив `viewers` и заполните своими данными:

```json
{
  "login": "viewer_login",
  "user_id": "",
  "facts": ["Любит головоломки"],
  "jokes": [],
  "avoid": ["Не шутить про личную жизнь"]
}
```

Используйте логин маленькими латинскими буквами, без `@`. Если указать Twitch user ID, карточка будет привязана к ID даже после смены логина. Каждое поле заметок допускает до 12 строк по 200 символов. Записывайте только сведения, которые допустимо передавать AI-провайдеру и повторять в эфире.

В оперативной памяти хранится до 10 пар «вопрос — ответ» для 1000 последних зрителей, которым бот успешно ответил. При превышении этого числа удаляется история зрителя с наиболее давним ответом; личные инструкции и карточки памяти сохраняются. История очищается после завершения процесса. В API передаются общий промпт, личная инструкция текущего зрителя (если включена), заметки о канале, карточка текущего зрителя, его история и новый вопрос.

## Ограничения и ошибки

- Вопрос обрезается до 400 символов, обычный ответ — до 400 без добавляемого `@логина`. Ответ публикуется одной строкой с упоминанием зрителя; вся строка ограничена 450 символами. У самостоятельных реплик действует собственная настройка длины.
- Вопросы обрабатываются последовательно; в очереди может ждать до 10 вопросов.
- После временных ошибок Twitch API (например, HTTP 429 или 503) подписка на награды повторяется через 5 секунд. Ошибки авторизации и отозванные разрешения требуют исправления настроек.
- Таймаут запроса к модели — 20 секунд. При временных ошибках, некорректном или пустом ответе бот пробует настроенные запасные модели по порядку, без повторов. После трёх сбоев основной модели она пропускается на 5 минут, если есть запасные модели. Ошибки авторизации AI не запускают перебор моделей.
- Запросы к основной и запасным моделям могут расходовать баланс провайдера.
- Возврат баллов не автоматизирован. При ошибке ответа, переполнении очереди или разрыве соединения проверьте журнал и при необходимости верните баллы вручную. Остановка процесса прерывает текущую работу; вопросы, поступившие во время отключения, могут быть пропущены.
- Если ответов нет, проверьте оба Twitch-аккаунта, точное название награды, обязательный ввод текста, доступность награды и ограничения чата для аккаунта бота.
- При ошибке AI проверьте Base URL, ключ, баланс и доступность всех указанных моделей у провайдера. API должен поддерживать поля `messages`, `max_tokens`, `stream` и текстовый ответ в `choices[0].message.content`.
- При ошибке `memory.json` проверьте JSON и структуру по шаблону.

Для диагностики передавайте текст ошибки без ключей и токенов.

## Проверка и сборка

В окружении с зависимостями из `requirements.txt`:

```powershell
python -m unittest discover -s tests -v
python tests/smoke_gui.py
python tests/smoke_testing.py
python tests/smoke_controls.py
python tests/smoke_prompt_builder.py
python -m pip install pyinstaller==6.22.3
python -m PyInstaller --noconfirm --clean --onefile --windowed --name TwitchAIBot --icon "assets/app.ico" --add-data "assets/app.ico;assets" --add-data "memory.example.json;." app.py
python tests/smoke_package.py
```

Готовый файл — `dist\TwitchAIBot.exe`. GitHub Actions запускает тесты и собирает приложение при отправке изменений в `dev`. Автоматические проверки не требуют Twitch-токенов и не вызывают платный AI API; реальное подключение проверяется отдельно со своими аккаунтами.

Документация Twitch: [IRC и служебные сообщения](https://dev.twitch.tv/docs/chat/irc/), [EventSub WebSocket](https://dev.twitch.tv/docs/eventsub/handling-websocket-events), [Device Code Flow](https://dev.twitch.tv/docs/authentication/getting-tokens-oauth/#device-code-grant-flow).
