# Разбор замечаний Gemini — 23 октября 2026

Основные три направления обоснованы: состояние интерфейса должно приходить из
структурированных событий, канал процесса удобнее регулярного чтения файла,
а подтверждение Twitch нуждается в отдельной карточке с копированием кода.
Готовые замены из отчёта нельзя переносить буквально.

## С чем не согласен

1. **«Задержка составит 0 мс».** Канал убирает интервал опроса в 250 мс, но остаются
   доставка данных, планирование Qt, разбор событий и отрисовка. Большие пачки нужно
   обрабатывать порциями, иначе моментальная обработка лога сама задержит анимации.
2. **Оценка нагрузки на диск без замеров.** Четыре чтения в секунду сами по себе не
   доказывают значительную нагрузку. Доказуемый недостаток прежнего решения —
   задержка уведомлений. Старый код уже дочитывал файл при завершении процесса.
3. **Предложенный DualStream не подходит для Windows EXE.** У оконной сборки
   PyInstaller Python-потоки stdout/stderr могут быть None. Ошибка записи в закрытый
   канал также не должна останавливать бота. Нужны поддержка наследуемого Windows
   handle и независимое сохранение журнала.
4. **Один декодер для двух независимых каналов.** Пакеты stdout и stderr могут
   заканчиваться посередине разных символов UTF-8. Их нельзя смешивать в одном
   декодере. В реализации выбран один объединённый канал QProcess и один декодер;
   Python-строки дополнительно сериализуются при записи из разных потоков.
5. **Неполная замена отображения состояния.** В предложенном коде нет обработки
   disconnected и сохранения существующего обновления рабочего пространства.
   Нельзя оставлять «работает» после разрыва связи или терять различие между
   сохранёнными настройками и настройками запущенного процесса.
6. **Локальные цвета и HTML карточки авторизации.** Белый код и фиксированный синий
   не учитывают светлую тему. Здесь используются общие компоненты Orbit, обычный
   текст для аккаунта и отдельная кнопка с проверенным адресом Twitch.
7. **Предложенная команда smoke-тестов.** Сценарии студии имеют main(), а не
   unittest.TestCase. Их нужно запускать как скрипты; импорт через unittest не
   выполняет эти сценарии. Удалять реальные токены и запускать живого бота для
   автоматической проверки тоже не требуется: тесты используют временные данные.

## Что исправлено

- Удалены текстовые правила для счётчиков, авторизации и статуса. Обычные строки
  только попадают в журнал; UI_EVENT и AUTO_EVENT обрабатываются как протоколы.
- Вместо таймера чтения файла подключён readyReadStandardOutput с MergedChannels.
  Файл bot-session.log продолжает независимо сохраняться. Однократное чтение
  архива остаётся только для ошибки запуска до открытия канала.
- Добавлены поддержка оконного Windows EXE без sys.__stdout__, UTF-8 независимо от
  кодировки консоли, сериализация полных строк, обработка закрытого канала,
  частичных записей и последней строки без перевода строки.
- UI разбирает не больше 100 строк за проход с бюджетом около 5 мс и обновляет
  состояние один раз за пачку. Неизменившиеся статусы не переоформляются заново.
- Завершение дочитывает канал и очередь до окончательного статуса. Новая сессия
  получает отдельное состояние; остановка и перезапуск не переиспользуют старый код.
- Карточка входа показывает роль и аккаунт, позволяет скопировать код и открыть
  Twitch. После истечения срока действия код недоступен для действий. При ошибке
  входа остаётся объяснение, а при остановке и завершении входа карточка очищается.
- Уточнена проверка адреса активации: HTTPS, разрешённый хост и путь, отсутствие
  userinfo и нестандартного порта. Отображение имени аккаунта не интерпретирует HTML.
- При GUI-проверках обнаружилось нативное падение в обработчике переходов. Тип
  события теперь читается явным вызовом QEvent.type в самом callback; дальше
  передаётся только enum. Скорости и визуальный рисунок переходов сохранены.

## Проверка

Пройдены 485 модульных тестов, существующие GUI-сценарии и новый
smoke_runtime_transport.py с настоящим дочерним QProcess без Twitch/API-запросов.
Он покрывает оба канала, побайтовый UTF-8, код и ссылку входа, обе темы, компактную
геометрию, пачки событий, ошибочные данные, EOF, остановку, перезапуск и сбой запуска.
Проверка Windows EXE дополнительно читает его вывод через subprocess и QProcess
в режиме --pipe --self-test, где Python stdout оконной сборки отсутствует.
Карточка дополнительно проверена при масштабе 125% и 150%. После изменения
обработчика переходов отдельно прошли 10 последовательных прогонов безопасности
и три полные матрицы экранов в обеих темах и размерах окна. Это результат
регрессии, а не доказательство отсутствия любых нативных ошибок Qt.
